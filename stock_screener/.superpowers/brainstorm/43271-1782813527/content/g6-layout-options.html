G6 / Deterministic Layout Options for US.NVDA

Goal: turn the current drifting fan into a stable root-centered layered circle, while keeping sector grouping and upstream / downstream / peer meaning.

A. G6 RadialLayout as Pre-Layout

Use G6 / @antv/layout radial only to calculate deterministic root-centered rings, then render with preset coordinates.

Pros

  • Native layered circle
  • Designed for hierarchical relationships
  • Has overlap controls

Cons

  • Need constrain direction sectors
  • Need post-process sector/hull grouping

B. Custom Deterministic Radial Tree

Keep no G6 layout; rewrite our layout as strict depth rings with fixed direction arcs and sector wedges.

Pros

  • Full control
  • Direction semantics preserved
  • Stable by construction

Cons

  • We already tried variants
  • More geometry to maintain
  • Harder to get polished quickly

C. G6 Combo / ComboCombined

Model each sector as a G6 combo, let G6 group containers carry the visual grouping.

Pros

  • Native group containers
  • Built-in combo interactions
  • Can replace hull plugin

Cons

  • ComboCombined defaults to force outside
  • More data/render refactor
  • Less appropriate for fast fix

Initial recommendation

Prefer A: G6 RadialLayout as a deterministic pre-layout. It directly targets the thing that is broken in the screenshot: root-centered layered circles. We can still keep upstream/downstream/peer as post-processed angle sectors and keep our aggregate/hull UI.
