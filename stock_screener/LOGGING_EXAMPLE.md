## 日志说明

### 符号含义
- ✅ `pass`: 通过筛选
- ❌ `fail`: 未通过筛选
- ⊝ `skip`: 跳过（数据不足）
- ⚠️ `error`: 执行错误

### 日志结构
1. **标题行**: 显示序号、状态、代码、名称
2. **基本信息**: 市值、PE、K线数据量
3. **筛选器结果**: 每个筛选器的详细信息
   - 状态图标 + 筛选器名称 + 结果
   - 原因说明
   - 详细数值
4. **总结**: 通过/失败/跳过的筛选器数量
5. **关键信息**:
   - 如果满足所有条件: 显示 🎉
   - 如果不满足: 列出未通过的筛选器和关键失败原因

### 阅读技巧
- 快速判断: 看标题行的 ✅/❌
- 了解原因: 看"关键失败原因"部分
- 详细分析: 查看每个筛选器的数值

---

## 使用场景

### 1. 验证筛选逻辑
通过日志验证每个筛选器是否按预期工作：
- 检查数值是否正确提取
- 检查判断逻辑是否正确
- 发现数据质量问题

### 2. 调试筛选条件
根据日志调整筛选条件：
- 看到很多股票因价格太低被过滤 → 降低 `price_min`
- 看到很多股票因 PE 过高被过滤 → 提高 `pe_max`

### 3. 分析筛选结果
了解为什么某些股票没有通过：
- 市值不足？
- PE 不在范围内？
- 数据缺失？

## 日志配置

日志输出由 `verbose` 参数控制，在 `api/screen_service.py` 中：

```python
run_screening_task(
    mysql_config=mysql_config,
    task_id=task_id,
    market=market,
    timeframe=timeframe,
    params=params,
    verbose=True,  # 设置为 True 启用详细日志
)
```

**当前配置**: `verbose=True`（默认启用）

如需关闭详细日志，将 `verbose` 改为 `False`。
