# 代码筛选工作台设计

## 背景

当前前端同时存在“单股选股”和自选股票列表筛选两类入口。单股入口虽然能执行 Python 规则链和原子规则，但没有完整复用自选列表的任务、结果、CSV、报告和 artifact 流程。为减少重复链路，后续统一为一个“代码筛选”工作台：输入一个股票代码就是单股筛选，输入多个股票代码就是自选列表筛选。

## 目标

- 删除旧的“单股选股”前端入口。
- 新增或改造为“代码筛选”页面。
- 所有代码输入任务统一调用 `POST /api/screening/custom-list-tasks`。
- 单股场景不再创建新的 `single_stock_runs`，而是作为 `codes` 长度为 1 的 custom-list 任务执行。
- 结果统一进入 custom-list / screening task 结果体系，复用已有任务详情、通过/未通过状态、CSV、联网 AI 报告和 artifact 下载。
- 页面视觉必须和现有后台工具风格一致，信息密度高、层级清晰、控件齐全，不做营销式页面。

## 非目标

- 不新增股票名称转代码能力，输入仍只接受股票代码。
- 不新增新的筛选执行后端链路。
- 不重做全市场筛选页面。
- 不迁移旧 `single_stock_runs` 历史数据到新任务体系。
- 不在本次设计里引入新的图表或报告格式。

## 前端信息架构

左侧导航删除“单股选股”，新增“代码筛选”。页面主体分为四块：

1. 任务参数区：市场、K 线周期、规则链、是否启用 AI 分析、是否发送飞书。
2. 股票代码输入区：支持一行一个代码、逗号分隔、空格分隔；页面提示“输入一个代码即单股筛选”。
3. 输入预检区：展示有效代码数、重复代码数、无效代码数；保留原始输入顺序。
4. 任务结果区：提交后展示任务状态，并提供跳转任务详情的入口。

页面不再区分“单股模式”和“批量模式”。是否单股由有效代码数量自然决定。

## UI 设计约束

- 保持当前 Web 前端的后台工具风格：白底面板、8px 内圆角、低饱和边框、蓝色主按钮、紧凑表格。
- 参数区使用表单网格，不做大 hero、不做装饰性渐变背景。
- 股票代码输入使用大文本框，适合粘贴多行代码；移动端单列展示，桌面端保持高信息密度。
- 预检结果使用小型指标块或紧凑提示条，避免占用过多垂直空间。
- 状态文案使用中文业务语言：`有效代码`、`重复跳过`、`代码无效`、`已通过`、`未通过`。
- 按钮文案使用 `创建筛选任务`，不要再出现 `开始单股分析`。
- 页面视觉要和“全市场筛选”“规则链”页面一致，样式复用现有 `.form-grid`、`.panel`、`.toolbar`、`.table-wrap` 体系。

## 数据流

提交时前端将输入拆分为 `codes[]`，并调用：

```json
{
  "market": "HK",
  "codes": ["HK.00700", "HK.09988", "03690"],
  "timeframe": "1d",
  "chain_key": "default_zuoyi_and_other",
  "enable_ai_analysis": true,
  "send_feishu": false
}
```

后端返回 custom-list job 后，前端进入任务等待态。任务完成后，前端读取 custom-list 结果接口，或复用现有 task detail 查询能力展示结果。

## 结果展示

任务详情页保留现有筛选结果表，并增强对代码筛选的表达：

- 按原始输入顺序展示结果。
- 状态包含：`已通过`、`未通过`、`代码无效`、`重复跳过`。
- 单个代码任务也使用同一张结果表，不再使用单股专用结果面板。
- 报告和 CSV 继续从 artifact 区下载；命名沿用当前市场信号复核报告命名规则。

## 错误处理

- 没有有效代码：阻止提交，提示 `至少输入一个有效股票代码`。
- 全部重复：阻止提交，提示 `没有需要运行的新代码`。
- 市场与代码格式不匹配：展示在预检区，不阻止其他有效代码提交。
- local_agent 未启动：保留现有 queued/running 状态提示，不额外新增弹窗。
- custom-list API 返回错误：使用现有 `.error` 样式展示中文错误。

## 兼容性

- 旧 `single_stock_runs` 数据保留在数据库中，但不再在前端提供入口。
- 后端可以暂时保留 `/api/screening/single-stock`，但新前端不再调用它。
- local_agent 继续支持旧单股任务一段时间不影响新流程；新流程全部通过 custom-list job 运行。

## 测试要求

- 前端构建通过。
- 输入一个代码时，请求体仍是 custom-list 结构，`codes.length === 1`。
- 输入多个代码时，预检统计和提交请求一致。
- 删除旧单股导航后，页面不可从导航进入旧 SingleStock 组件。
- 代码筛选任务创建后能进入任务详情，并展示 custom-list 结果。
- 移动端宽度下表单不横向溢出，文本框和按钮保持可点击尺寸。

## 决策记录

- 选择方案 C：统一“股票代码筛选”工作台。
- 旧“单股选股”入口删除，不保留快捷入口。
- 单股能力不消失，只作为输入一个代码的代码筛选任务存在。
