# 任务级 AI 报告、ES 存储与报告查询

实施依据：用户在本对话批准的完整方案。所有入口取消 CSV（含临时文件），一逻辑任务一报告，多市场合并；仅入选股票分析，无入选正常完成但无报告；AI/ES 失败不能完成；仅新任务。报告成功存 ES 后统一释放全市场锁。复用 MySQL JSON 断点、现有 Redis/RQ、搜索与模型工厂和 Markdown 内容，不改规则、评分、SQL 默认规则或 Graphify，不新增数据库表。

## Task 1: 结构化 AI 与报告内容

移除 AI 读写 CSV 的运行依赖；分析服务直接接收 ScreeningSignalRow，返回 Markdown 和结构化分析。复用批量搜索/LLM、缓存及渲染，完整验证成功结果，空输入不调用供应商。单股内部分析不创建临时文件。先写离线测试验证，再改代码。

## Task 2: ES、任务断点与报告接口

新增最小报告存储职责：screening_reports_v1，CJK 文本、精确元数据、确定性任务报告 ID，refresh=wait_for。现有任务 JSON 保存入选数据/分析断点/草稿，ES 失败重试只写草稿；完成前检查已有 ES 报告处理丢失确认。公开 GET /api/reports、GET /api/reports/{report_id}、POST /api/reports/retry，复用鉴权、错误、分页，不返回草稿或大正文列表。

## Task 3: 所有入口与任务生命周期

全市场、自定义列表、两个单股路径、定时入口统一报告产出，使用父 job_id/run_id，定时建立父任务。移除输出 CSV/MD 文件及关闭最终报告的选项；持锁直到 ES 成功或确认失败/终止，恢复当天竞争锁。只重试报告阶段不重新筛选，旧令牌不可发布。飞书仅摘要、报告 ID、可选 WEB_PUBLIC_URL 链接。保留原任务筛选明细，只有成功入库报告可查。

个股入口同样遵守“开启任务 → 生成个股报告 → ES 可查询后完成”。报告 ID 使用 `single_stock-{run_id}`，报告状态和 ID 返回任务详情；未完成草稿只供内部恢复，不通过任务详情公开。报告失败不改变股票原筛选通过结果，ES 入库重试不得重新筛选或调用报告模型。未通过筛选仍按统一约定正常完成、不生成报告。

## Task 4: 页面、部署与验收

新增报告查询、关键词分页、详情 Markdown 安全渲染与直达链接，任务展示报告状态/查看/重试。Docker/Podman 同步增加 ES 9.5.5、Python client 9.5.1、2GiB、自动堆、禁用 ML、单主分片零副本、独立数据卷、健康检查、TLS/CA 与仅报告索引权限，不发布 ES 公网端口。补文档/快照恢复说明；独立 Redis/ES 模拟数据测试、浏览器模拟验证和构建，不运行真实筛选或线上部署。

调用预算：100 只入选、缓存未命中默认约 5 个 LLM 主批次、10 个公司搜索逻辑批次，另现有市场/热点搜索与配置中的拆分/回退；合并无需额外 LLM。正常 1 次 ES 文档写，列表和详情各 1 次 ES 查询。纯存储重试供应商调用 0。
