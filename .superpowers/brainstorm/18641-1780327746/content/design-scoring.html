2️⃣ 缺失模块处理：从"50分中性"改为"置信度惩罚"

❌ 当前逻辑
缺失模块直接给 50.0 分（中性），参与加权求和。

问题：
• 5 模块全缺 = 总分 50，可能高于阈值 70？不会，但 3 模块缺失 + 2 模块表现好 → 可能通过
• 50 分没有表达"我们不知道"的语义
• 数据不全的股票和数据完整的股票无法区分
✅ 目标逻辑
方案：缺失模块不参与加权，降低置信度

① 缺失模块 不贡献分数也不贡献权重
② 仅用可用模块计算加权总分
③ confidence_score = 可用模块数 / 5 × 100
④ 当 confidence_score < 40（即 <2 模块可用）时 → result="skip"，不管总分多少
⑤ 总分旁边展示 基于 3/5 模块

示例：Macro(70), Company(80), Valuation(缺), Industry(缺), Trading(60)
→ 总分 = (70×0.30 + 80×0.25 + 60×0.10) / (0.30+0.25+0.10) = 72.3
→ confidence = 3/5 = 60%
→ 展示: "总分 72.3（基于 3/5 模块）→ WATCH"

4️⃣ aggregate_rule_scores 重构

当前 vs 目标
当前逻辑：
aggregate_rule_scores() 扫描 filter_details，将 strategy_category="macro" 的 macro_score 提取为 macro_score，其余 pass 策略 → technical_score=100，fail → 0。然后 0.6×technical + 0.4×macro → final_score

目标逻辑：
aggregate_rule_scores() 直接读取 EnterprisePotential 输出的 total_score + module_scores 作为权威分数。技术策略器的 pass/fail 转为 Trading 模块的增强信号，不再独立算分。

写入 DB 的字段保持兼容：
technical_score → Trading 模块分
macro_score → Macro 模块分
final_score → total_score
score_details → 新增 module_scores + decision + holding_period + confidence
