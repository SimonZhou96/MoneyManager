评分模型优化：三种方案对比

核心矛盾：两套评分独立运行，宏观/行业/公司事件三维度均被重复评估

📋 方案总览

A

保守合并 — 以 B 为主，A 降级为数据源

改动范围：中等（macro_strategies.py + screen_service.py）

废弃 MarketIntelMacroScoreStrategizer 的独立评分角色，其 LLM 评分能力转为 EnterprisePotential 的 Company/Industry 模块增强输入。统一使用五因素权重体系。

优点

  • 消除双重评分冲突，单一真相来源
  • 保留 A 体系的 LLM 分析能力不浪费
  • 报告中的评分来源统一、可解释

缺点

  • MarketIntel 的 6 维子评分体系被废弃
  • aggregate_rule_scores 的 0.6/0.4 权重逻辑需重构
B

分层分级 — A 做快速过滤，B 做深度评估

改动范围：小（rule_chain DSL + screen_service 参数）

保留两套体系但明确分工：A 作为快速宏观面过滤（低阈值50分），B 作为深度五因素评估。规则链 DSL 支持"阶段门控"：先过 A 再进 B，减少深度评估的股票数量。

优点

  • 改动最小，两套代码都不需要大改
  • 快速过滤减少 LLM 调用量（省钱）
  • 两阶段门控逻辑清晰：先粗筛后精评

缺点

  • 双重评分依然存在，报告可能有两套分数
  • 两阶段阈值需独立调参，维护成本增加
C

彻底统一 — 单引擎可配置评分

改动范围：大（新建 unified_scoring 模块，重构 potential_analysis 和 macro_strategies）

设计统一的 UnifiedScoringEngine，支持模块化评分器热插拔。五因素权重 + 子维度权重全可配置（DB 驱动）。LLM 评分和规则评分统一接口，可选择每模块的评分方式。

优点

  • 评分体系完全可配置、可扩展
  • 支持市场差异化阈值（HK/US/A 各自调参）
  • 新增评分维度无需改核心代码

缺点

  • 改动量大，需要重构两个模块
  • 过度设计风险 — 当前 5 维度是否真需要热插拔？

🎯 推荐：方案 A（保守合并）

理由：两套评分体系的重叠度太高（宏观、行业、公司事件三维度完全重复评估）， 继续维持双轨只会增加维护负担和结果不一致性。方案 A 以更成熟的 B 体系（五因素） 为主框架，把 A 体系的 LLM 分析能力保留为增强输入，既消除了冲突， 又不浪费已有的 LLM 管线投入。改动可控，风险低。

📐 合并后的目标架构

统一评分引擎（UnifiedEnterpriseScorer）
五模块权重：M:30% | I:25% | C:25% | V:10% | T:10%（保持 B 体系权重）

Macro规则型 MacroScorer（阈值打分）+ 可选 LLM 增强（MarketIntel 数据作为补充证据）
IndustryIndustryScorer + SignalAnalysis LLM 热点标签注入（保持现有逻辑）
CompanyCompanyScorer + SignalAnalysis LLM 事件/新闻增强 + MarketIntel 公司事件证据
ValuationValuationScorer（PE/PB/PEG/EV_EBITDA）— 不变
TradingTradingScorer（涨跌/波动/趋势）+ 可选技术信号增强（来自规则链策略器结果）

MarketIntel 的新角色：不再独立输出 macro_score，而是作为 Macro/Industry/Company 模块的可选 LLM 增强数据源，当 MarketIntel Service 可用时提升评分质量，不可用时规则型评分正常工作（fail-open）。
