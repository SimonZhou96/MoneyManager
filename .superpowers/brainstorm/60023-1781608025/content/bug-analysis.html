Bug 分析：选择已有链 → 画布不加载

追踪了从下拉框选择到画布渲染的完整数据流，找到了 4 个 Bug

🔴 Bug 1（主因）：新建链后不重置 chainKey，导致重选同一链时 React 跳过了渲染

Bug 复现路径
1️⃣ 用户在编辑链 "左一战法+宏观标签"，画布正常显示
state: chainKey = "zuoyi_with_macro_enhanced"
2️⃣ 用户点击 ＋ 新建
❌ startNewChain() 重置了 editor 但没有调用 setChainKey('')
state: chainKey 仍然是 "zuoyi_with_macro_enhanced"
3️⃣ 用户从下拉框再次选择 "左一战法+宏观标签"
❌ setChainKey("zuoyi_with_macro_enhanced") — 和当前值相同
❌ React Object.is 比较 → Bail out，不触发重渲染
state: chainKey 仍然是 "zuoyi_with_macro_enhanced"
4️⃣ useEffect([selectedChain?.chain_key]) 不触发（依赖值未变）
5️⃣ setEditor 从不被调用 → visualExpression = 空
6️⃣ 画布空白

对比：deleteChain 正确地先重置了 chainKey

❌ startNewChain (line 1889-1899)
const startNewChain = () => {
  setEditor({
    timeframe: '1d',
    chain_key: '',      // ← 重置了 editor
    chain_name: '',
    ...
  })
  // ❌ 缺少 setChainKey('') — 下拉框未重置！
}
✅ deleteChain (line 1956-1967)
const deleteChain = async () => {
  await fetch(...)
  setChainKey('')        // ✅ 先重置
  startNewChain()         // ✅ 再清编辑器
  loadRules()
}

🟡 Bug 2-4（次要）

Bug 位置 影响
2️⃣ 下拉框 value 只用 chain_key，多周期链可能重复 main.tsx:1984-1986 同 key 不同周期的链，find() 返回第一个，可能加载错误的表达式
3️⃣ expressionToFlow 异常被静默吞掉 RuleChainEditor.tsx:65-67 catch 只调 resetCanvas() 无日志，用户看到空白以为是"没加载"
4️⃣ loadRules 闭包过时覆盖 chainKey main.tsx:1801-1809 API 返回时使用了 fetch 前的 chainKey，可能错误重置为默认链

🔧 修复方案对比

A

最小修复（只修 Bug 1）

在 startNewChain 中加一行 setChainKey('')，deleteChain 里已有的模式。10秒改完。

优点

  • 秒修
  • 零风险

缺点

  • Bug 2-4 仍在
  • 遇到特殊 case 仍可能出问题
B

完整修复（修 Bug 1-4）

修所有4个Bug + 加 console.error 日志用于调试。20分钟。

优点

  • 覆盖所有已知问题
  • 加错误日志便于后续排查
  • 多周期链也可正确处理

缺点

  • 改动稍多
  • 需测试多周期场景
C

先确认是否能复现，再决定修哪些

打开浏览器调试 → 按 Bug 1 路径操作 → 看控制台日志 → 确认后再修。

优点

  • 先验证再动手
  • 不盲目修

缺点

  • 需要启动前端
  • 多一步操作
